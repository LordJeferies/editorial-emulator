Qué problemas resuelve

Planear en listas se vuelve confuso

Cuando hay muchas piezas, cuesta ver carga, orden y balance semanal.

El plan y el feed viven separados

Un calendario puede verse bien en papel y sentirse repetitivo al simular la red real.

Automatizar suele romper contexto

Un agente externo necesita trabajar sobre los mismos datos, no sobre una copia desconectada.

Cómo lo resuelve

PLAN

3 vistas, un solo estado

Board, Timeline y Agenda editan exactamente el mismo escenario.

FEEDS

Mobile + Desktop

Instagram, TikTok, LinkedIn, YouTube y Facebook con Grid, Feed o Player según corresponda.

MCP

Agentes sobre el mismo Supabase

ChatGPT/Codex/Claude u otro cliente MCP puede leer y modificar escenarios, planner y biblioteca.

Planner

Board

Tipo Trello/Kanban. Arrastra entre los 7 días.

Timeline

Semana compacta para comparar densidad y orden.

Agenda

Lista precisa con controles para mover y reordenar sin depender del drag.

Puedes añadir de 3 formas: 1. arrastrar; 2. “Añadir a…” → elegir día; 3. “+ Añadir” dentro del día. Cambiar de vista NO borra ni duplica.

Bienvenida y progreso

Pantalla de bienvenida

Explica Plan, Feeds y MCP/Cloud al entrar. Puedes indicar que no se muestre completa cada vez.

Barra de carga arriba

Muestra porcentaje y qué está haciendo la app. La interfaz sigue utilizable durante operaciones normales.

Bloqueo sólo cuando hace falta

Si una operación no puede continuar de forma segura en paralelo, aparece un overlay explicando por qué debes esperar.

Cloud visible

Conectando, pendiente, sincronizando, sincronizado, offline o error también se reflejan como actividad.

MCP

Agente MCP ↓ Editorial Emulator MCP local ↓ Supabase / public.editorial_state workspace = editorial-os ↓ Realtime Web / PWA / Desktop

Puede hacer

  • escenarios: listar, crear, duplicar, renombrar, borrar;
  • planner: añadir, mover, reordenar, quitar y batch;
  • biblioteca: contenido, marcas, pilares, familias;
  • feeds: preview por plataforma;
  • validación y backups.

Seguridad

  • login real del usuario Supabase;
  • sin service_role;
  • confirmación para acciones destructivas;
  • backup automático antes de cada mutación;
  • preserva campos desconocidos del payload.
Guía completa MCP

Cloud y datos

Local-first

La UI guarda localmente primero para responder rápido. Supabase sincroniza después.

Fuente compartida

`public.editorial_state`, `workspace_key = editorial-os`, payload `version: 9`.

PWA

En iPhone: Safari → Compartir → Añadir a pantalla de inicio.

Desktop Mac

La `.app` usa WKWebView y carga esta misma GitHub Page, así que el frontend se actualiza sin reinstalar el wrapper.
