Controla Editorial Emulator desde un agente.

El MCP permite que ChatGPT, Codex, Claude u otro cliente compatible lea y modifique escenarios, planner, biblioteca y feeds usando el mismo Supabase que la app.

Configurar MCPVer código

Cómo funciona

Agente MCP ↓ stdio Editorial Emulator MCP local ↓ login Supabase del usuario public.editorial_state workspace = editorial-os ↓ Realtime Web / PWA / Desktop Mac

Una sola fuente de verdad

El MCP no mantiene otro archivo o base paralela. Trabaja sobre el mismo payload `version: 9` que comparten Editorial Emulator y Editorial OS.

No automatiza clicks

Opera directamente sobre los datos compartidos. Es más estable que intentar controlar la UI con coordenadas o browser automation.

Instalación

1 · Instala dependencias

cd ~/Downloads/editorial-emulator/mcp
chmod +x install.sh
./install.sh

2 · Configura el cliente MCP

{
  "mcpServers": {
    "editorial-emulator": {
      "command": "node",
      "args": ["/Users/TU_USUARIO/Downloads/editorial-emulator/mcp/server.mjs"],
      "env": {
        "EDITORIAL_SUPABASE_EMAIL": "TU_EMAIL",
        "EDITORIAL_SUPABASE_PASSWORD": "TU_PASSWORD",
        "EDITORIAL_WORKSPACE": "editorial-os"
      }
    }
  }
}

Credenciales

La URL y la anon/public key se leen automáticamente de `supabase-config.js`. Sólo debes aportar email y contraseña de tu usuario de Supabase mediante variables de entorno. No uses service_role, secret key, database password ni PAT.

Criterios para que un agente trabaje bien

Antes de escribir

  • leer el escenario actual;
  • usar IDs reales;
  • comprobar que el contenido no exista ya;
  • separar análisis de ejecución cuando el cambio sea importante.

Al modificar

  • usar batch para cambios relacionados;
  • no borrar campos desconocidos;
  • pedir/usar confirmación para operaciones destructivas;
  • validar después de cambios grandes.

Planner

  • Lunes=1 ... Sábado=6, Domingo=0;
  • `content_id` es plantilla reutilizable;
  • `instance_id` es la pieza concreta colocada;
  • Board/Timeline/Agenda son vistas del mismo estado.

Recuperación

  • cada mutación crea backup automático;
  • se guardan los últimos 8;
  • puedes restaurar un backup concreto;
  • después valida el estado.

Ejemplos simples

Crear semana

“Crea un escenario llamado Semana CRM desde Base JOC empezando el 5 de octubre.”

Mover contenido

“Mueve el carrusel principal del martes al jueves y colócalo primero.”

Auditar

“Revisa esta semana y dime si Instagram, TikTok y LinkedIn están balanceados. No cambies nada todavía.”

Aplicar cambios

“Aplica la reorganización aprobada en un solo batch y valida el estado al terminar.”

Crear contenido

“Crea una pieza reutilizable Caso CRM perdido por seguimiento para LinkedIn e Instagram, L2, Video.”

Deshacer error

“Lo último quedó mal. Busca el backup anterior, restáuralo y valida que el workspace esté bien.”

Importante: la app debe estar conectada a Cloud

El MCP escribe en Supabase. Para que una ventana Web/PWA/Desktop vea el cambio inmediatamente, inicia sesión desde el indicador Cloud dentro de Editorial Emulator. Si no está abierta, verá los cambios la próxima vez que sincronice.
