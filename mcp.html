Cómo usar el MCP, paso a paso.

El MCP permite que un agente compatible lea y modifique Editorial Emulator sin automatizar clicks. Trabaja sobre el mismo Supabase y el mismo workspace que usan la Web, la PWA y la app de Mac.

1. Qué hace realmente

ChatGPT / Codex / Claude / otro cliente MCP ↓ stdio Editorial Emulator MCP local ↓ login con tu usuario Supabase public.editorial_state workspace = editorial-os payload = version 9 ↓ Realtime Editorial Emulator Web / PWA / Desktop

Una sola fuente de verdad

El MCP no crea otra base de datos. Lee y escribe el mismo estado editorial que usan Editorial Emulator y Editorial OS.

Más estable que controlar la interfaz

No mueve el mouse ni depende de coordenadas. Usa herramientas estructuradas como crear escenario, mover pieza, reordenar un día o auditar feeds.

La app debe tener sesión Cloud

Para recibir cambios de inmediato en Web/PWA/Desktop, esa superficie debe estar conectada a Supabase con una sesión válida.

Las operaciones destructivas requieren confirmación

Vaciar un plan, eliminar un escenario o restaurar un backup exige confirmación explícita y el MCP crea backup antes de cada mutación.

2. Instalación en Mac

La forma recomendada es usar el script de configuración para macOS. Instala dependencias, valida Node, guarda tus credenciales en el Keychain de macOS y crea un launcher seguro.

1

Actualiza el repo

cd "$HOME/Downloads/editorial-emulator"
git fetch origin
git checkout main
git reset --hard origin/main
2

Ejecuta el setup

cd "$HOME/Downloads/editorial-emulator/mcp"
chmod +x setup-mac.sh
./setup-mac.sh
3

Ingresa tus credenciales

El script te pide el email y la contraseña de tu usuario Supabase. Se guardan en el Keychain local, no en el repo.

4

Copia la configuración MCP

El script imprime un bloque genérico para conectar el launcher local a tu cliente MCP.

No pongas secretos en GitHub

No uses service_role, database password, GitHub PAT ni pegues contraseñas en archivos versionados. El servidor usa la anon/public key del frontend + tu login real.

3. Conectar un cliente MCP

La configuración exacta depende del cliente, pero el principio es el mismo: el cliente debe lanzar el wrapper local generado por el setup.

{
  "mcpServers": {
    "editorial-emulator": {
      "command": "/Users/TU_USUARIO/.local/bin/editorial-emulator-mcp"
    }
  }
}

4. Casos de uso reales

Estos son los patrones recomendados. El agente debe leer antes de escribir, usar IDs reales y separar análisis de mutación cuando el cambio sea importante.

CASO 1

Quiero saber qué hay ahora

Muéstrame los escenarios actuales y dime cuántas piezas tiene cada uno.
  1. Lista escenarios.
  2. Lee el plan sólo si hace falta.
  3. No modifica nada.
editorial_list_scenariosLectura
CASO 2

Quiero crear una semana nueva

Crea un escenario llamado "Semana campaña CRM" desde Base JOC, empezando el 2026-10-05.
  1. Confirma la marca o usa JOC si está indicado.
  2. Crea el escenario.
  3. Devuelve el nuevo scenario_id.
  4. Valida que tenga 7 días válidos.
editorial_create_scenarioEscritura + backup
CASO 3

Quiero añadir contenido a un día

En el escenario "Semana campaña CRM", añade un clip de webinar al miércoles.
  1. Busca contenido equivalente con editorial_list_content.
  2. Obtiene el content_id real.
  3. Añade al día 3.
  4. Lee el plan para verificar.
editorial_list_contentLectura
editorial_add_contentEscritura
CASO 4

Quiero mover una pieza

Mueve "Carrusel principal" del martes al jueves y ponlo primero.
  1. Lee el plan.
  2. Encuentra el instance_id real.
  3. Mueve al día 4, índice 0.
  4. Comprueba el resultado.
editorial_get_planLectura obligatoria
editorial_move_itemEscritura
CASO 5

Quiero reorganizar varias cosas de una sola vez

Pasa el webinar al lunes, elimina el meme emocional del viernes y añade un testimonio al domingo.
  1. Lee el estado actual.
  2. Resuelve IDs reales.
  3. Construye una sola operación batch.
  4. Aplica una única mutación lógica.
  5. Valida el estado.
editorial_apply_batchRecomendado para cambios relacionados
CASO 6

Quiero auditar el plan sin cambiarlo

Analiza esta semana. Dime si Instagram, TikTok y LinkedIn están balanceados, si hay días saturados y si repetimos demasiado el mismo formato. No cambies nada todavía.
  1. Lee el plan.
  2. Genera preview de feeds por plataforma.
  3. Compara conteos, días y formatos.
  4. Devuelve diagnóstico y propuesta.
  5. Espera aprobación antes de escribir.
editorial_preview_feedsVista derivada, no modifica datos
CASO 7

Quiero crear un contenido reutilizable

Crea una pieza "Caso CRM perdido por seguimiento" para LinkedIn e Instagram, L2, formato Video.
  1. Busca primero si ya existe algo equivalente.
  2. Sólo crea si es una unidad editorial reutilizable.
  3. Devuelve el nuevo content_id.
  4. Añádelo al plan únicamente si también se pidió.
editorial_list_contentEvitar duplicados
editorial_create_contentCrear biblioteca
CASO 8

Quiero probar una variante sin tocar el original

Duplica este escenario como "Semana CRM · variante agresiva" y trabaja solamente en la copia.
  1. Duplica el escenario actual.
  2. Confirma el scenario_id nuevo.
  3. Realiza cambios sólo en esa copia.
editorial_duplicate_scenarioA/B seguro
CASO 9 · DESTRUCTIVO

Quiero vaciar un plan

Vacía por completo el escenario X.
  1. El agente debe advertir que es destructivo.
  2. Debe identificar correctamente el scenario_id.
  3. Sólo ejecuta con confirm:true.
  4. El MCP crea backup antes de vaciar.
editorial_clear_planRequiere confirmación
CASO 10

Quiero deshacer un error grande

Lo que acabamos de hacer quedó mal. Vuelve al estado anterior.
  1. Lista backups.
  2. Selecciona el backup anterior correcto.
  3. Explica qué va a restaurar.
  4. Restaura con confirmación.
  5. Valida después.
editorial_list_backupsLectura
editorial_restore_backupRequiere confirmación
editorial_validate_stateVerificación final
CASO 11

Quiero crear pilares y familias

Añade un pilar "CRM y sistemas" y una familia "Errores de CRM" dentro de ese pilar.
  1. Crea primero el pilar.
  2. Toma el ID devuelto.
  3. Crea la familia usando ese pillar_id.
  4. No inventa IDs.
editorial_create_taxonomyTaxonomía
PATRÓN RECOMENDADO

Brief completo para un agente

Revisa el escenario de esta semana. No borres nada.
Detecta días saturados, repetición de formatos y plataformas desatendidas.
Propón una reorganización.
No cambies nada hasta que yo apruebe.
Cuando apruebe, aplícala en un solo batch y valida el estado al terminar.

Este patrón separa diagnóstico, aprobación y ejecución. Es la forma recomendada para cambios editoriales importantes.

5. Reglas que el agente debe respetar

Leer antes de escribir

Primero escenario, plan o biblioteca. Después mutación.

No inventar IDs

instance_id identifica una pieza concreta del plan; content_id una pieza reutilizable.

Batch para cambios relacionados

Una reorganización múltiple debe quedar como una sola operación lógica cuando sea posible.

Confirmar destrucción

Eliminar escenario, vaciar plan o restaurar backup requieren confirmación.

Validar después

Tras cambios grandes, ejecutar editorial_validate_state.

No duplicar contenido

Buscar en biblioteca antes de crear una pieza equivalente.

7. Si algo falla

El cliente no ve el MCP

Comprueba que la ruta del launcher sea correcta y que el cliente haya sido reiniciado después de cambiar su configuración.

Error de Node

Se requiere Node.js 20+. El setup de Mac lo comprueba antes de instalar.

Login de Supabase falla

Verifica email/contraseña. La anon key se lee del repo; no necesitas service_role.

La app no refleja el cambio

Abre Editorial Emulator, pulsa Cloud y confirma que existe una sesión válida. Luego sincroniza o vuelve a abrir.
